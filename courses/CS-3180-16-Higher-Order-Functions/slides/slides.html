FP in non-functional languages

First Class Fns

  • Functions are a type
  • They can saved as variables (without being called)
  • Passed into functions (often called a "callback")
function greet() {
    console.log("Hello world!");
}

// callbackFn is an argument (first class function)
function repeatFn(callbackFn) {
    callbackFn();
    callbackFn();
}

const fn = greet;
repeatFn(fn);

"Lambda" Expressions

  • Often, callbacks are implemented as lambdas
  • (Javascript calls theses "arrow functions")
// callbackFn is an argument (first class function)
function repeatFn(callbackFn) {
    callbackFn();
    callbackFn();
}


// in-line lambda of function greet(){...} 
const fn = () => console.log("Hello world!");

repeatFn(fn);

Inlining

  • Equivalently, something like this
  • Adding full {}s and indentation
  • Consumer doesn't care (or even see) when parameter fn is called
// callbackFn is an argument (first class function)
function repeatFn(callbackFn) {
    callbackFn();
    callbackFn();
}

repeatFn(() => {
    console.log("Hello world!")
});

Returning Functions

  • Beyond accepting functions
  • We can also return functions
  • "Function Factories"*
  • Useful in some circumstances

Returning Functions

  • Returns a fn we can call later
  • Pay attention to knowns vs. unknowns
function createMultiplier(factor) {
    // number is a parameter, not a value    
    return function(number) {
        return number * factor;
    };
    // arrow fn equivalent
    // return (number) => number * factor
}

const double = createMultiplier(2);
const triple = createMultiplier(3);

console.log(double(5));
console.log(triple(5));

Higher-Order Functions

  • Call a Higher-Order Function (HOF), a function that either:
  • Accepts function as a parameter (callback)
  • Returns a function
  • Or both!
  • This concept is how FP can scale for large programs

List Processing

  • Very commonly used for processing lists
  • Hence why these ideas mostly come from Lisp
  • Let's start re-build the most common version of this (in JS)
  • Work backwards into Lisp

Map Function

  • Let's write a HOF that applies a function to every value in a list
  • Traditional called "map"
  • Have our function accept:
  • The list to process
  • Callback function to transform
  • (We'll assume this function always "looks" like how we want)

Map Function

  • Usually instead implemented as a method for List
function map(list, fn){
    for (let i = 0; i < list.length; i++) {
        // transform the ith elem
        const newValue = fn(list[i])
        list[i] = newValue
    }
    return list;
}

const list = [1, 2, 3, 4, 5]
const updatedList = map(list, (i) => {
    return i + 1;
});

console.log(updatedList)

HOFs in Lisp

  • HOFs come from Lisp
  • Especially useful when recursively lists
  • Let's see how this looks

Lisp HOFs

  • Analyze this code
  • You might expect this to work
(defun my-map (list fn)
    (labels ((my-map-inner (remaining)
            ; when lets us handle nil recursive case easier
            (when remaining
                 (let ((new-value (fn (car remaining))))
                    (cons 
                        new-value 
                        (my-map-inner (cdr remaining)))))))
        (my-map-inner list)))

(defun add-one (value)
    (+ value 1))

(format t "New List: ~S~%" (my-map '(1 2 3) add-one))

Lisp Namespacing

  • The "Global Namespace" is really two namespaces
  • One for functions, one for variables
  • (fn ...) will lookup fn in function namespace
  • (funcall fn ...) to fix this
  • Also, we'll use #' when we pass add-one to get the function itself
  • (Some dialects fix this behavior)

HOFs in Lisp

  • Fixing that, you arrive at:
(defun my-map (list fn)
    (labels ((my-map-inner (remaining)
            ; when lets us handle nil recursive case easier
            (when remaining
                ; funcall -> look up in variable namespace
                (let ((new-value (funcall fn (car remaining))))
                    (cons 
                        new-value 
                        (my-map-inner (cdr remaining)))))))
        (my-map-inner list)))

(defun add-one (value)
    (+ value 1))

; #' look up as function type
(format t "New List: ~S~%" (my-map '(1 2 3) #'add-one))

Standard Library HOF

  • What we are really doing:
  • Mapping the car of the list
  • Through our function
  • Common usecase, standard library has a function for this
  • mapcar

Map Car

  • Looks something like this:
  • mapcar can also accept multiple lists
  • Parallelizes the application

(defun add-one (value)
    (+ value 1))

(defparameter *original-list* '(1 2 3))

(let ((new-list (mapcar #'add-one *original-list*)))
    (format t "New list was: ~S~%" new-list))

Map Car

  • We can use the lambda function if we don't want to defun globally

(defparameter *original-list* '(1 2 3))

(let 
    ((new-list 
    (mapcar #'(lambda (value) (+ 1 value)) *original-list*)))
        (format t "New list was: ~S~%" new-list))

Other HOFs in Lisp

  • mapcar will get 90% there in most cases
  • A few others include:
  • maplist: Like mapcar, but pass CDR each time
  • funcall: Calls a function (which we already used
  • apply: Like funcall, but unpack arguments
  • reduce: Fold elements into a value

OOP HOF implementations

  • Such a useful construct, most OOP languages
  • Attempt to implement something like this
  • Take a brief look at how you might do something like this with objects

HOF OOP

  • Standard Library Provides "Functional Interfaces"
  • Just need to turn every HOF type into an interface
interface Mappable {
    public int apply(int i);
}
// use generics instead of ints
public static List<Integer> map(List<Integer> list, Mappable m){
    for(int i = 0; i < list.size(); i ++){
        int newValue = m.apply(
            list.get(i)
        );
        list.set(newValue, i);
    }
    return list;
}

Streams

  • In Java, you must convert Collection type into a "stream"
  • Apply HOFs (interfaces impls.) to that stream
  • Convert the stream back into a Collection
  • (This is secretly a FP function called a Monad)
  • Let's see it
List<String> names = Arrays.asList(
    "John", "Sarah", "Jack", "Emily"
);
List<String> result = new ArrayList<>();

for (String name : names) {
    if (name.startsWith("J")) {
        result.add(name.toUpperCase());
    }
}
System.out.println(result);

 // transforms into this declarative version
List<String> names = Arrays.asList(
    "John", "Sarah", "Jack", "Emily"
);

List<String> result = names.stream()
    .filter(name -> name.startsWith("J"))
    .map(String::toUpperCase) //wrap this method call in a lambda
    .collect(Collectors.toList());

System.out.println(result);

Summary

  • A function is higher-order if it:
  • Accepts a function as a parameter
  • Or returns a function (or both)
  • Native to languages with first-class functions
  • mapcar is the most common one in Lisp
  • Not an idea exclusive to FP languages
