Language Specifications

  • Most languages are actually not the executor
  • A language is just its specification
  • Usually a 100 pg. PDF file
  • Maintained by ISOs
  • Some have a "reference implementation"
  • "This impl. works as it should, build to that spec"

Language Specifications

  • Specifications are often made after the initial implementation
  • Many implementations of that standard
  • Each with their own quirks

"Development Kit"

  • Overly complicated for Java
  • JDK: series of binaries
  • Some implement just pieces
  • Most languages: implementation of the executor
  • When implementations build off each other, we call that a "dialect" of the other language

Lisp Languages

  • Lisp Family
  • Not Implementations
  • Racket is a dialect of Scheme, etc

Steel Bank CL

  • We will be using Steel Bank Common Lisp

  • The CL specification does not state how CL should be executed

SBCL

lisp.sh

#!/bin/bash

# LISP execution script based on AUR package:
# https://github.com/xyproto/lisp


# Goal with this is to sort of eliminate the REPL feel for students
# irl lisp programs are almost never ran as a REPL

clear

LISP_INTERPRETER=sbcl

if ! command -v $LISP_INTERPRETER >/dev/null 2>&1; then
    echo "sbcl could not be found"
    echo "Please ensure it is installed before running"
    exit 1
fi


if [ -z $1 ]; then
    echo "Please provide a filename as the first argument"
    exit 1
fi

if [ ! -f $1 ]; then
    echo "Could not find the file named \"$1\""
    exit 1
fi

# force sbcl to run in interpretter mode
# this is 100% slower, but more in line with traditional lisp

$LISP_INTERPRETER \
--noinform \
    --noprint \
    --no-userinit \
    --no-sysinit \
    --disable-debugger \
    --quit \
    --eval '(setf sb-ext:*evaluator-mode* :interpret)' \
    --load "$1" \
    --end-toplevel-options
    # this is not in the help menu, but is documented at https://linux.die.net/man/1/sbcl

Hello world

  • Parentheses are EXTREMELY important
  • Cannot use them wherever
  • format
  • t for standard out
  • ~% for new line
; semi-colon for comments :(
; common lisp hello world
(format t "Hello, world!~%")

Case Insensitivity

  • Casing doesn't matter in Lisp
  • Technically converts everything* to uppercase
  • I recommend lowercase
  • Make it easy on your syntax highlighter

(format t "Hello, world!~%")
(FORMAT T "Hello, world!~%")
(fOrMat T "Hello, world!~%")

What's going on here?

  • t is effectively a primitive type
  • t and nil are the basic types
  • Most things are a list*
  • (Lisp actually has a much more interesting sub-typing system)
  • Lisp is strong and dynamically typed

Prefix Notation

  • We commonly use infix notation
  • Operator is between values:
  • ((1 * 3) + (2 + 2))
  • Lisp uses prefix notation:
  • Operator comes before the values
  • (+ (* 1 3) (+ 2 2))

Code as Lists

  • Lisp code is a series of nested parentheses
  • ~S print in readable format
  • Really pay attention to these parentheses
  • Cardinal sin of Lisp formatting:
  • "A line shall never consist of only parentheses" 
(format t "~S~%" 
    (* (+ 1 3) 4))

Why???

  • Why on earth would you want this?
  • Less ambiguity:
  • 8 / 2 ( 2 + 2)
  • All operators are functions
  • Much easier to parse

Notes

  • Lisp doesn't really have reserved words
  • "Keywords" don't exist in the traditional sense
  • *Technically there are KEYWORDS, but those are loaded at runtime and not built into the spec.
  • Basically everything is a library function/macro
  • +, /, <, >, =

Summary

  • Lisp is a family of functional languages
  • CommonLisp is one specification
  • SBCL is the implementation
  • Lisp uses prefix notation
  • Basically everything is a function/macro
