Interpreted Languages

  • The `python` binary
    is an Interpreter
  • It will execute your
    code line by line
  • By the time it gets to the
    call, it hasn't defined `add`

REPLs

  • Interpreted languages like Python, often ship with REPLs
  • Read, Evaluate, Print, Loop
  • Which is what we get when we type `python` directly

Compiled Languages

  • Java and C(++) are compiled languages
  • A compiler turns source code into a form closer to machine code
  • BEFORE it is actually executed
  • Let's look at some C code to see this process
  • Pass our code to `gcc`
  • Produces an executable file
  • Executable -> Machine Code

#include <stdio.h>

int main(){
    printf("Hello, World!");

    return 0;
}
        

gcc main.c -o main.exe
➜ ./main.exe 
Hello, World!%
➜

Java's Compilation Process

  • Java does things a bit differently
  • JDK contains multiple binaries
  • `javac`: Compile Java code
  • `java`: Execute compiled Java code

Java's Compilation Process

  • `javac`: Produces Java ByteCode
  • `java`: Executes the bytecode in a "VM"
  • Bytecode is still *closer* to machine code than source code
  • This is how Java can see `add`

Multi-Pass Compilation

  • Java compiler will pass over your code multiple times
  • Will still read the whole thing at once
  • C's compiler actually will not do this
  • Hence why header files exist
  • Some interpreted languages can get away with this
  • Javascript -> Hoisting

Interpreter Quirks

  • Because interpreters can't look ahead
  • Just execute sequentially
  • The concept of a `main` is basically made up
  • But it is often best practice
  • Let's see that in Python

__name__

Check if the current file is being executed directly with __name__ 

def main():
    print("hello world")

if __name__ == "__main__":
    main()
  • If this feels a little wrong
  • That's okay, we will revisit next time
  • MUST go at the end

Compilers are strict

  • Compilers get to REQUIRE a main
  • I.e. don't produce an executable, UNLESS all requirements are fulfilled
  • Interpreters => FAFO
  • Produce errors at compile-time
  • Instead of *exclusively* run-time like interpreters

Is one better?

  • Generally python is used for quick scripting
  • Compilers can do some crazy optimizations
  • Compilers are generally slow
  • But the compiled code can execute much quicker
  • Any reason why you would want an interpreted language?

Compiler Complications

  • The truth is, most interpreted languages have some sort of in-line compiler
  • Python does (depending on the implementation) e.g. pycache
  • Lisp, Javascript, etc.
  • Just-in-Time compiler

Aside: Transpilers

  • Distinguish between High and Low level languages
  • High Level -> Java, Python, etc.
  • Low Level -> Assembly, C, etc.
  • Transpilers take something of the same level to the same level
  • Except people often just call them compilers anyway?

Summary

  • Compilers:
  • Turn High -> Low
  • Read the whole file at once
  • Produce a new file
  • Generally Faster
  • Interpreters:
  • Read and execute line by line
  • Can be ran in a REPL
  • Generally slower
Like all things, we are skipping much nuance
