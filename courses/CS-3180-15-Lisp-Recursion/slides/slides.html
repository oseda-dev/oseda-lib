Factorial

  • You have likely seen factorial done before
  • Good practice to see
  • Get into the recursive mindset
(defun factorial (n)
  (if (<= n 1)
      1
      (* n (factorial (- n 1)))))

(format t "N! was ~S~%" (factorial 3))

Get Penultimate

  • Missing some edge cases
  • No explicit returns
  • Can make guard clauses harder
(defun get-penultimate (s)
    (let ((cur (car s)))
        (if (null (cdr (cdr s)))
            cur
            (get-penultimate (cdr s)))))


(format t "penultimate was ~S~%" (get-penultimate '(ALICE BOB CHARLIE DEREK ELI)))

Defun Namespace

  • Consider the namespace here
  • factorial can call factorial
  • factorial is defined both within AND outside the function
  • Keep this scope in mind as we move forward

Flet

  • Allows you to scope functions
  • First parameters is ALL your functions you want to scope
  • Body is the scope that allows you to call those functions
  • CANNOT be recursive
  • CANNOT call each other
    • 
(flet (functions...) (code that calls those functions))

Flet

  • Entire form evaluates to the body
  • Which calls your local functions
(format t "~S~%" 
  (flet ((double (value) 
         (* value 2))
       (square (value) 
         (* value value))
        (triple (value)
            (* value value value)))
  (triple (double (square 3)))))

Labels

  • Same as flet
  • Except the functions can be recursive
  • They can also call each other
  • Often just used for simple recursive functions
    • (labels ((factorial (n)
           (if (<= n 1)
               1
               (* n (factorial (- n 1))))))
  (factorial 5))

Labels

  • Canonical example for labels
  • You'll likely need this on your project
(defun parity (value)
  (labels ((is-even (x)
             (if (zerop x)
                 t
                 (is-odd (- x 1))))
           (is-odd (x)
             (if (zerop x)
                 nil
                 (is-even (- x 1)))))
    (if (is-even value)
        'even
        'odd)))

(format t "~S~%" (parity 9))

Tail Calls

  • Recursion is expensive
  • Every new call -> new stack frame
  • Load all the data each time
  • In most functional languages, some additional optimizations occur
  • Under specific conditions
  • Let's start in a non-FP language

Tail Calls

  • Javascript Example
  • The last thing this function does is wait for factorial to finish
  • EVERY stack frame must resolve before we return
    • function factorial(n) {
  if (n === 1) return 1;
  return n * factorial(n - 1);
}

Tail Calls

  • If the LAST thing the function did
  • Was recursive call
  • We wouldn't need to return address of the previous function
  • We wouldn't have to wait
  • We would need a way to pass all the work forward
  • Commonly done via a parameter

Tail Calls

  • VERY last thing we do is a recursive call
  • Executor can re-use the same stack frame
  • New parameter becomes previous return value
  • Make recursion as fast as iteration
function factorial(n, accumulator = 1) {
  if (n === 0) return accumulator;
  return factorial(n - 1, n * accumulator); // tail call
}

Tail Calls in Lisp

  • This idea is critical for writing fast Lisp code
  • Prefer tail calls if possible
  • Harder to visualize
  • (&optional is special form that allows optional + default params)
  • Porting the code, you get something like this:
(defun factorial (n &optional (acc 1))
  (if (= n 0)
      acc
      (factorial (- n 1) (* n acc))))

TCO in Lisp

  • TCO is not actually defined in the CommonLisp spec
  • Some dialects like Scheme require it
  • Needs enabled to require it
  • Done within the defun
  • (first argument to progn 
(declare (optimize (speed 3) (debug 0)))

Summary

  • Functions are a little more complicated than just defun
  • Scope function(s) with flet
  • Use labels if you need them to see/call each other
  • Tail Call Optimization allows executors to reuse the last stack frame
