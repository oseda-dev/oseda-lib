Interface instances

  • Can't alter contract, need N as constructor param
class Task implements Runnable {
    private int sleepForSeconds;
    
    public Task(int sleepForSeconds){
        this.sleepForSeconds = sleepForSeconds;
    }

    @Override
    public void run(){
        try {
            Thread.sleep(sleepForSeconds * 1000);
        } catch (InterruptedException e) {
            System.out.println("Something went wrong");
        }
        System.out.println("Done sleeping!");
    } 
}

public class AnonTypes1 {
    public static void main(String[] args) {
        Runnable task = new Task(5);
        
        Thread t = new Thread(task);

        t.start();
    }
}

Anon. Inner Classes

  • Use { } after instantiation (of interface, directly)
  • Dropping some try/catch boilerplate
public class AnonTypes2 {
    public static void main(String[] args) {

        Runnable task = new Runnable() {

            @Override
            public void run() {
                try {
                    Thread.sleep(5 * 1000);
                } catch (Exception e) {}

                System.out.println("Done sleeping!");
            }
        };

        Thread t = new Thread(task);
        t.start();
    }
}

Anon. Inner Classes

  • Can implement multiple methods within { }
  • Best when only *used* once
  • Implementation is all we care about
  • Execute implementation later
  • Still a lot of boilerplate
  • Can we do better?

Lambda Expressions

  • ( params ) -> { implementation }
  • Run has no parameters
  • As well as no return
  • Could call .run(), but Java calls that under the hood
Runnable task = () -> {
    try {
        Thread.sleep(5 * 1000);
    } catch (Exception e){}
};

Thread t = new Thread(task);
t.start();

Lambda Expressions

  • Parameters do not need a type
  • Static Typing -> Java will infer the types
  • Only works for single-method interfaces
  • Call those "Functional Interfaces"
interface Drivable {
    public void drive(int distance);
}

public class Lambdas {
    public static void main(String[] args) {
        
        Drivable d = (distance) -> {
            System.out.println("Drives " 
                + distance 
                + " miles");
        };
        
        d.drive(5);
    }

Behavior

  • We can assign variables to lambdas
  • Behavior, as a variable
  • Pass these around throughout our program
  • Execute on demand
  • Abuse of OOP
  • Behavior as data is inherently an idea from the Functional Paradigm

Non-First Class Citizens

  • We have created an object to sit in place of a function
  • Java has to jump through a lot of hoops for this
  • There is no type for a Function
  • Wrap as an object instead
  • In Java, functions are not "First-Class"

Python Function Types

  • Python has a type for functions
  • add is just a variable
  • That you *can* call
  • You don't strictly have to
def add(a, b):
    return a + b

# add is reference to its implementation
# we dont actually have to call it with (...)
print(add)

print(add(1, 1))

First-Class Citizens

  • We can pass these function types around
  • (Type hinting becomes tricky)
  • Work just like data, that we can ()
def add(a, b):
    return a + b

def mult(a, b):
    return a * b

def perform_operation(fn, a, b):
    return fn(a, b)

result = perform_operation(add, 3, 4)
print(result)

result = perform_operation(mult, 3, 4)
print(result)

First-Class Citizen

  • This property of being able to pass functions as arguments:
  • Call them First-Class functions
  • One of the fundamental ideas of functional programming

Python Lambda Expression

  • Lambda Expressions are not unique to OOP hacks
  • Universally applicable
  • Python: lambda params: expression
def perform_operation(fn, a, b):
    return fn(a, b)

result = perform_operation(
    lambda a, b: a - b,
    5, 3
)

print(result)

Summary

  • Anonymous Types are commonly used to store behavior
  • Different languages need to jump through different hoops to do this
  • Functions as types = First Class Functions
  • Not all languages support this
  • Lambda Expression: Quick, anonymous functions
