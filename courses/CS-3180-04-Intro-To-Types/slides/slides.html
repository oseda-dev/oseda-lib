C's Types

  • C has a few useful types:
  • `int`: Integer
  • `char`: Character
  • `floats`: Floating point numbers
  • `true/false`: Booleans via stdbool.h
Let's use them in code

C's Types

  • But does it really?:
  • `int`: => Integers
  • `char`: => Integers in a trenchcoat
  • `floats`: => Stored as 32-bit ints
  • `true/false`: => 1/0
  • Pointers* => Address = Integer
  • Arrays => Pointers => Integer

C is lying

  • C treats basically every type as int under the hood
  • Abstraction on binary again
  • You still need to EXPLICITLY label types
  • FORTRAN was one of the first to do this*

Type Coercion

  • Because everything is an int
  • C will seamlessly convert between types
  • Implicitly convert between your types
  • We'll call this behavior "Type Coercion"

Type Coercion


#include <stdio.h>

int main() {
    int a = 10;
    // ascii 65
    char b = 'A'; 
    float c = 5.5;

    float result = a + b + c; 
    
    printf("%f", result);
    return 0;
}

Better Example

#include <stdio.h>

// expect int
void printNumber(int num) {
    printf("number was: %d\n", num);
}

int main() {
    double myPi = 3.14159;
    
    // c converts double to int
    printNumber(myPi); 
    
    return 0;
}

Weak Typing

  • This property of converting between types
  • A weakly-typed system
  • Note: The first example actually works in Java
  • Strings are usually an edge case

Strong Typing

  • If instead, a language REQUIRES that your types match
  • We will call that a strongly typed language
  • Java is an example of a strongly typed language

Typing Strength

  • Type strength is always a spectrum
  • A strong type system usually:
  • EXPLICITLY cast between types
  • Prevent operations on invalid types
  • Minimize silent conversions

Python?

  • How is python a *strongly* typed language?
  • We saw before how fast-and-loose it plays
  • Let's look at a non-string example

def calculate_total(price, quantity):
    return price * quantity

print(calculate_total(4.99, 3))  

print(calculate_total(4.99, "three"))

# you can actually catch these errors
# introduce try/except
try:
    print(calculate_total(4.99, "three"))
except TypeError as e:
    print(f"Oopsies: {e}")

What's different?

  • Well, let's do it in Java and see
  • Type checking still occurs in both
  • Difference: WHEN the type check occurs

Dynamic Typing

  • We will call this property of waiting until RUN-TIME to check your types
  • Dynamic typing
  • Types are associated with the data, not the variable

Static Typing

  • Opposite of this: static typing
  • Variable types are checked prior to RUN-TIME
  • Usually, this means they are checked at COMPILE-TIME
  • Types are bound to the variable itself
  • Also a spectrum

Typing

Wrap Up

  • Two ways of categorizing type systems
  • Explicitness of Coercion (strong/weak)
  • Time when types are checked (static/dynamic)
  • Most languages fall somewhere in between
