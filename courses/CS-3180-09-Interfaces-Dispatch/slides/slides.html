Contract

  • Validity of Interfaces are resolved at compile time
  • If a class implements an interfaces
  • Must implement its methods
  • Compile-time contract
interface Drivable {
    public void driveToWork();
    public void driveToSchool();
}

Declared Types

  • Because they can function as declared types
  • Can pass them into methods

Dynamic Dispatch

  • Java's static typing will ensure this is a valid vall
  • At compile time
  • But dynamically look up the correct implementation at runtime
  • Just looking at this snippet -> No clue what implementation is called
public static void commute(Drivable d){
    d.driveToWork();
    d.driveToSchool();
}

Dynamic Dispatch

  • No longer a one-to-one mapping of declaration to implementation
  • Dynamic Lookup of a method implementation
  • Call this behavior dynamic dispatch
  • Harder for a compiler to optimize
  • Allows for SIGNIFICANT abstraction
  • Basis for all OOP code at scale

Dispatch Implementations

  • C++ uses the virtual keyword
  • Look's up values in a VTABLE

Summary

  • Inheritance makes function lookup complicated
  • Static Dispatch: Resolve the callee prior to execution
  • Dynamic Dispatch: Resolve the callee at runtime
  • Some languages use a separate type for implementation contracts
  • Key to resolving dynamic dispatch
